# 10 — Content Upgrade Standard (normative)

**Applies to:** every article written, upgraded, localized, or reviewed on `https://ural-travel.pages.dev` — by a
person or by an AI tool. **Baseline:** 17 October 2026, measured against `dist/` built from `main`.

> This file is the acceptance contract for **one article**. It does not decide *what* to write next; that is the active
> cluster plan — [`BANKING-FOREX-CLUSTER-PLAN.md`](BANKING-FOREX-CLUSTER-PLAN.md) (opened 19 October 2026), or
> [`UMRAH-CLUSTER-PLAN.md`](UMRAH-CLUSTER-PLAN.md) for the Umrah cluster — and the active row in
> [`CONTENT-QUEUE.md`](CONTENT-QUEUE.md), sequenced by [`CONTENT-OS.md`](CONTENT-OS.md) §1. Where a planning document and
> this file disagree about **how a post must be wired and verified**, this file wins. Where they disagree about **what to
> build next**, the cluster plan wins.

## 0. The three-file rule — read this before auditing any post

On 17 October 2026 an external audit reported that the women's / mahram article (`blog-17`) had *"no internal links,
no affiliate widgets"*. Both statements were false. The article had four curated internal links and a KiwiTaxi CTA,
rendered in English and Bengali. The audit had grepped `src/data/blogContent.ts` for `internalLinks`, found none, and
concluded the feature was missing — but that file contains **article bodies only**.

**Never conclude that a metadata field is missing from a grep of one file.** Check the three locations below, then
check the built HTML (§8). A field can be absent from the body and still be rendered; it can also be present in
metadata and never reach the page.

| What you are looking for | English | Bengali |
|---|---|---|
| Article body (markdown-ish prose) | `BLOG_BODY` — `src/data/blogContent.ts` | `BENGALI_BLOG_OVERRIDES[slug].content` — `src/data/bengaliContent.ts` |
| Title, summary, category, dates, author, read time | `BLOG_DATA` — `src/constants.ts` | override fields — `src/data/bengaliContent.ts` |
| `references` | `BLOG_DATA[].references` | `BENGALI_BLOG_OVERRIDES[slug].references` (falls back to the EN post) |
| `internalLinks` | `BLOG_DATA[].internalLinks` | `BENGALI_BLOG_OVERRIDES[slug].internalLinks` (**no fallback**) |
| `affiliateCTA` | `BLOG_DATA[].affiliateCTA` | `BENGALI_BLOG_OVERRIDES[slug].affiliateCTA` |
| `inlineFigure`, cover image | `BLOG_DATA[].inlineFigure`, `BLOG_IMAGE_MAP` | override, shared asset |
| Scheduled drafts | `content/blog/*.md` → `src/data/*.generated.ts` | same file |

Scheduled posts are generated by `npm run generate:scheduled` (`scripts/generate-scheduled-blogs.ts`). **Never
hand-edit a `*.generated.ts` file**; edit the Markdown draft and regenerate.

## 1. Where each piece is rendered

| Surface | Source | Consequence for authors |
|---|---|---|
| Static article HTML | `scripts/prerender.ts` | This is what Google reads first. Links, references and marketing placements must be here. |
| Live article UI | `src/routes/BlogPostRouteView.tsx` | Adds the contextual inline link, the CTA widget and the related box after hydration. |
| Article metadata | `src/constants.ts` / `bengaliContent.ts` | Changing it changes listings, schema, sitemap and the article. |
| Sitemap `lastmod` | `src/data/contentMeta.ts` (`CONTENT_UPDATED`) + per-post `updatedAt` | A material edit needs a truthful date, or the sitemap lies. |

**Critical asymmetry:** the English prerenderer appends up to four related posts from `getRelatedBlogPosts()` on top
of `internalLinks`, so an English article always shows at least four blog anchors. **The Bengali renderer does not.**
It renders only `BENGALI_BLOG_OVERRIDES[slug].internalLinks`, filtered to paths that have a Bengali page. That is why
a post can look healthy in English and be bare in Bengali — and why §3 requires links to be written twice.

---

## 2. Definition of done — six gates

An article is finished only when all six are true, in **both locales**:

1. **Body** — answers the page's one job, with claims backed by dated primary sources (§5, §6).
2. **Sources** — at least three references, primary first, with `name`, `nameBn`, `url` (§5).
3. **Links** — at least four internal links, of which at least two are blog→blog and at least one is a hub or money
   page; no dead, duplicate or self targets (§3).
4. **Commerce** — one relevant `affiliateCTA` (or an explicit decision that there is no relevant partner) (§4).
5. **Locale parity** — the Bengali twin carries the same facts, the same caveats and its own explicit links (§6.4).
6. **Build proof** — `npm run lint`, `npm run build`, `npm run verify:build` exit 0, and the new anchors exist in
   `dist/` for both locales (§8).

A green `verify:build` does **not** satisfy gates 1, 2 or 5. CI cannot read prose.

## 3. Internal linking contract

### 3.1 The map

```
/umrah (pillar)  ──  cluster children (blog-11 … blog-22)
      │                    │
      │                    ├── lateral: 2–5 sibling posts
      │                    ├── up: pillar / category hub
      │                    └── commerce: /flights, /hotels, /visa, /costs, /tools
      └── every child must be reachable from at least two siblings
```

Link **up** to the pillar or hub, **across** to genuine siblings, and **out** to the one money page that completes the
task. Do not link every sibling from every post; that produces a link farm with no hierarchy.

### 3.2 Rules

- **R1 — Minimum.** Every new or upgraded article defines **≥4** `internalLinks`: **≥2** blog→blog, **≥1** hub or
  money page. Target steady state is 3–5 siblings plus 1–2 hubs.
- **R2 — No orphans.** A new article must be added to **at least two existing articles** in the same release wave.
  Publishing a page that only the index links to is not a release.
- **R3 — No dead, duplicate or self targets.** `/blog/<slug>` must exist; a path may appear once; never link the
  article to itself. Aliases (`/pre-departure`, `/indexing`) resolve to `/sitemap` — write the canonical path.
- **R4 — Anchors are descriptive and varied.** Name the target's subject ("Nusuk app and Rawdah permit
  step-by-step"), not "read more", "click here" or "this guide". Vary the wording for the same target across posts.
  A phrase, not a sentence.
- **R5 — Placement matters.** `internalLinks[0]` is injected as a contextual link inside the body after hydration.
  Put the single most task-relevant link first. The remaining links render in the related box.
- **R6 — One locale is not the other.** `getLocalizedBlogs("bn")` assigns `internalLinks: bn.internalLinks` with no
  English fallback. A Bengali override that omits the array ships an article with **zero** editorial links. Write the
  Bengali array explicitly, in canonical English paths (`/blog/...`, `/umrah`); the renderer localizes them to
  `/bn/...`.
- **R7 — Rendered, not declared.** A link that exists in `BLOG_DATA` but not in `dist/` is not a link. Verify with §8.
- **R8 — Relevance over volume.** Link the page a reader needs next, not every page in the cluster. A visa page does
  not need a hotel link unless hotel choice changes the visa decision.
- **R9 — Auto-related is a floor, not a strategy.** `getRelatedBlogPosts()` fills the English related box from
  category, tags and title similarity. It cannot tell whether the match answers the reader's next question. Curate
  the links you care about; do not rely on the fallback.

### 3.3 What the renderer actually does

| Locale | Related blog anchors | Hub / money anchors | Extra |
|---|---|---|---|
| EN | every valid `internalLinks` blog path + up to 4 `getRelatedBlogPosts()` results | separate "Plan your trip" list | `internalLinks[0]` also appears inline in the body |
| BN | only `BENGALI_BLOG_OVERRIDES[slug].internalLinks` whose path has a Bengali page | same list, localized | no auto-related supplement |

### 3.4 Worked example — `blog-17`

```
Nusuk app & Rawdah permit        → /blog/nusuk-app-…-rawdah-permit      (sibling, task step)
Hotel zones & Haramain train     → /blog/makkah-madinah-hotel-zones-…  (sibling, logistics)
Umrah with elderly parents       → /blog/umrah-with-elderly-parents-…  (sibling, audience variant)
DIY Umrah portal & calculator    → /umrah                              (up-link, pillar)
```

Three siblings, one pillar, no dead targets, mirrored in Bengali. The English page additionally shows the ihram
guide because the auto-related fallback supplies it; Bengali does not — which is acceptable because the curated four
are present in both.

## 4. Affiliate and widget contract

### 4.1 Registry

All partner URLs live in `AFFILIATE_LINKS` (`src/components/AffiliatePartners.tsx`). `affiliateCTA.provider` is a
closed union of those keys. Never hardcode a `.tpo.li` URL in content, a component or a prerender string; resolve
through `resolvePartnerUrl()` or `<PartnerLinkButton />` so paused programmes fall back correctly.

### 4.2 Relevance matrix

| Reader friction | Partner keys | Place it when | Do **not** place it when |
|---|---|---|---|
| Comparing airfare / open-jaw routes | `aviasales`, `kiwi` | the article compares routes, carriers, baggage or fare timing | the article is about a visa rule or a religious procedure |
| Airport arrival and transfer | `kiwitaxi`, `welcomePickups`, `getTransfer` | arrival logistics, family/elderly travellers, late-night landing, luggage | the article is domestic rail/bus, or the reader is already at the hotel |
| Connectivity and app-based permits | `airalo`, `yesim` | Nusuk/Rawdah QR, multi-country trips, family tracking, remote work | the article has no app, QR or connectivity step |
| Attractions, passes and activities | `klook`, `kkday`, `tiqets`, `goCity` | city itineraries, skip-the-line, day trips, experience comparisons | visa, customs, mahram, medical or legal-procedure articles |
| Hotel-stay search | `klook` | the article compares areas, seasons or booking windows | the article is about a permit that hotels cannot influence |
| Car rental and road trips | `qeeq` | self-drive routes, inter-city road legs | the destination is served by rail and the article says so |
| Luggage storage / long layover | `radicalStorage` | layovers, early check-in, last-day storage | the article is about checked-baggage rules |
| Flight disruption / compensation | `airhelp` | delays, cancellations, denied boarding, compensation | routine planning articles with no disruption scenario |
| Creator referral | `TRAVELPAYOUTS_REFERRAL_URL` | only inside the labelled "For Travel Creators" block | anywhere a reader might mistake it for a booking link |

### 4.3 Rules

- **A1 — One primary CTA per article.** A second, unrelated CTA splits intent and reads as a advertorial.
- **A2 — The CTA must answer the article's own friction.** If the page is about mahram rules, a family transfer
  solves the arrival problem; a city attraction pass does not. If nothing is relevant, ship **no** CTA and say so in
  the queue row.
- **A3 — Provider keys only.** `affiliateCTA.provider` must be a key of `AFFILIATE_LINKS`; CI rejects anything else.
- **A4 — Specific copy, not a slogan.** Name the airport, city or route the reader is actually using. "Landing at
  Jeddah Terminal 1 in Ihram?" is specific; "Book your transfer today!" is not.
- **A5 — Disclosure and attributes.** The rendered CTA carries the site disclosure; outbound affiliate anchors use
  `rel="noopener noreferrer sponsored"`. Never add `nofollow` to editorial references.
- **A6 — Promotions expire.** Any coupon, sale or price claim in CTA copy must pass through `isPromoActive()` and
  `sanitizeExpiredPromoText()`. Do not hardcode a promo date into prose.
- **A7 — The CTA is client-rendered.** `BlogPostRouteView` renders `affiliateCTA` after hydration, so the **static
  HTML contains no partner URL** (verified: zero `kiwitaxi` occurrences on the blog-17 page). If a commercial link
  must be crawlable, add a placement to `MULTI_PARTNER_BLOG_PLACEMENTS` / `RADICAL_STORAGE_BLOG_PLACEMENTS` /
  `TRAVELPAYOUTS_REFERRAL_BLOG_PLACEMENTS` in `scripts/prerender.ts`. That is a code change, not a copy change.
- **A8 — No fake relevance.** Never attach a partner to a page whose intent it does not serve merely to raise
  revenue. The owner reviews this as an editorial decision.

## 5. Sources and external links

- **S1 — Three sources minimum** for a new or materially upgraded article. Primary first: ministry, regulator,
  airport, airline, operator, property. A news article or another blog is a lead, not a source.
- **S2 — Shape.** `{ name, nameBn, url }`. Both names are required; the Bengali page renders `nameBn`. No affiliate
  URLs, no URL shorteners, no tracking parameters that expire.
- **S3 — Cite in prose with `[n]`.** Bodies contain markers, not raw URLs. The highest marker must not exceed
  `references.length`.
- **S4 — Date the check.** Set `updatedAt` only when you actually re-checked the claim; the renderer prints
  "References checked: <date>" from it. Do not set a fresh date on unchanged copy.
- **S5 — Attributes.** References render as `target="_blank" rel="noopener noreferrer"`. Affiliate anchors add
  `sponsored`; editorial sources never do.
- **S6 — Cite the operator, not the intermediary.** If a competitor's guide states a fare, cite the airline or
  operator page it used. Do not make a competitor the authority.
- **S7 — Volatile facts.** Put the date basis beside the number ("checked 17 October 2026"), state the condition
  (date, room, occupancy, class), and if the source cannot be re-verified, **delete the claim** rather than soften it
  into vagueness.
- **S8 — External links belong in the sources block.** Inline external links are for the primary document a reader
  must open to complete the task, not for background reading.

## 6. Voice and structure

### 6.1 House voice

Calm, direct, locally informed, candid about uncertainty. Speak to a traveller planning from Bangladesh; BDT first
when a verified price exists; name the passport and departure context. Lead with the reader's friction and answer
the primary question without hype. Never imply URAL booked, tested, interviewed or measured anything unless the
repository contains that evidence. Full contract: [`AI-WRITING-PROMPTS.md`](AI-WRITING-PROMPTS.md) §0.5.

### 6.2 Upgrade pattern — the "conversational" style, defined

The style used in the October 2026 upgrade wave (the Cox's Bazar pillar is the reference article) is not loose
chattiness. It is a fixed five-beat structure:

1. **"Who this guide is for"** — one sentence naming the reader, their origin and their decision. No generic intro.
2. **"Quick Answer"** — the dated, specific answer in the first two sentences, with citation markers.
3. **Question-shaped headings** — "Cox's Bazar Airport Status in 2026: International Flights Still Suspended", not
   "Airport".
4. **The practical detail** — cost, condition, document, step, with the date basis beside it.
5. **The caveat beside the claim** and the next action, linked (§3).

Write to one traveller, in the second person, in short factual sentences. Conversational means *direct*, not casual:
no filler ("In today's world…"), no jokes in a religious or legal section, no "we" unless the repository contains the
evidence for it.

```text
YES  Who this guide is for: families leaving Dhaka who need a plan they can verify today.
YES  Quick Answer — As of 16 October 2026, three routes operate: … [5]. International flights are not operating: … [2].
NO   Planning a trip to Cox's Bazar? Read on to discover everything you need to know!
```

### 6.3 Factual vs practical sections

Factual sections (rules, fees, eligibility) run definition → rule → attribute → source. Practical sections
(choices, trade-offs, planning) may use first/second person and editorial judgement, but may not invent experience,
reviews or community answers. Component and visual rules: [`CONTENT-SYSTEM-V2.md`](CONTENT-SYSTEM-V2.md).

### 6.4 Bengali parity

The Bengali article must answer the same questions with the same eligibility, prices, date basis, exclusions,
warnings, route steps and source links. It is not a summary and not a translation of the English page's layout. It
must also carry its own `internalLinks` (R6).

### 6.5 Banned phrases

"hidden gem", "insider secret", "you won't believe", "guaranteed approval", "100% free" without a source,
"best" without stated criteria, invented "we tested / we stayed / our team visited", and urgency that the calendar
does not support.

## 7. Procedure

1. **Read the queue row and cluster plan.** Confirm the URL, the action (new / update in place) and the page's one job.
2. **Inspect the live representation.** Open the rendered EN and BN pages and the three source locations in §0.
   Record the current link count, CTA provider and reference count.
3. **Build the claims ledger** ([`CONTENT-OS.md`](CONTENT-OS.md) §3, prompt in `AI-WRITING-PROMPTS.md` Stage 2).
4. **Rewrite the body** with `[n]` markers and the §6 pattern.
5. **Wire the metadata:** `internalLinks` (≥4, ≥2 blog), `affiliateCTA` (or a recorded decision to omit),
   `references` (≥3), `updatedAt`.
6. **Write the Bengali twin:** body, summaries, references with `nameBn`, and its own `internalLinks`.
7. **Update the dates truthfully:** per-post `updatedAt` for the article; `CONTENT_UPDATED` in
   `src/data/contentMeta.ts` only when non-blog, data-driven content changed under its documented date contract.
8. **Build and verify:** `npm run lint && npm run build && npm run verify:build`.
9. **Prove it in `dist/`** (§8), then update the queue row and the claims ledger.

## 8. Verification

```bash
npm run lint
npm run build
npm run verify:build
```

Then inspect the built pages — not the browser, not the source:

```bash
# every curated blog link is a real anchor (EN)
grep -o 'href="/blog/[^"]*"' dist/blog/<slug>.html | sort -u

# the Bengali twin has its own anchors (BN)
grep -o 'href="/bn/blog/[^"]*"' dist/bn/blog/<slug>.html | sort -u

# the sources block rendered
grep -o 'Sources for this guide' dist/blog/<slug>.html

# expected: 0 for a CTA-only article — the widget is client-rendered
grep -c 'kiwitaxi.tpo.li' dist/blog/<slug>.html
```

If a count is lower than the metadata says, the link did not ship. Fix the renderer or the metadata; do not report
the metadata as proof.

## 9. What CI enforces

`npm run verify:build` now includes a **content contract** block:

| Check | Scope | Fails when |
|---|---|---|
| Link integrity | all posts | an empty link list, a non-absolute path, a self-link, a duplicate path, or a `/blog/` target that does not exist |
| Provider integrity | all posts | `affiliateCTA.provider` is not a key of `AFFILIATE_LINKS` |
| Flagship minimums | Hajj & Umrah | fewer than two blog→blog links, or no affiliate CTA |
| Rendered anchors | Hajj & Umrah | a curated `/blog/` link is absent from the EN page, or the BN page has fewer than two `/bn/blog/` anchors |
| Negative control | fixtures | the validator stops catching a deliberately broken fixture |

The validator is tested against broken fixtures on every run, so a refactor cannot silently neuter it.

**Not enforceable by CI:** whether a link is the *right* next step, whether the CTA answers the page's friction,
whether a source is primary, whether the Bengali text is a real localization, or whether a claim is true. Those
remain human gates.

The build also prints a non-blocking **`[content-debt]`** report: posts with no blog link, no CTA, no references, and
posts with no editorial inbound link. Green CI is not a pass on those items; it is a record of them.

## 11. Pre-publish checklist

Copy this into the queue row or the pull request.

```text
[ ] Queue row exists; URL, action and one job confirmed
[ ] Body rewritten in house voice; [n] markers resolve to references
[ ] ≥3 primary references with name + nameBn + url
[ ] updatedAt set to the real check date
[ ] ≥4 internalLinks: ≥2 blog→blog, ≥1 hub/money, none dead/duplicate/self
[ ] Article added to ≥2 existing posts (no new orphan)
[ ] affiliateCTA chosen by §4.2, or omission recorded
[ ] Bengali twin: same facts, own references, own internalLinks
[ ] lint + build + verify:build exit 0
[ ] EN and BN pages grepped in dist/ for the new anchors and sources block
[ ] Queue row and claims ledger updated
```
