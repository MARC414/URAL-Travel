**Applies to:** every article written, upgraded, localized, or reviewed on `https://uraltravel.co.uk` — by a
person or by an AI tool. **Baseline:** 17 October 2026, measured against `dist/` built from `main`.

## 0. The three-file rule — read this before auditing any post

On 17 October 2026 an external audit reported that the women's / mahram article (`blog-17`) had *"no internal links,
no affiliate widgets"*. Both statements were false. The article had four curated internal links and a KiwiTaxi CTA,
rendered in English and Bengali. The audit had grepped `src/data/blogContent.ts` for `internalLinks`, found none, and
concluded the feature was missing — but that file contains **article bodies only**.

**Never conclude that a metadata field is missing from a grep of one file.** Check the three locations below, then
check the built HTML (§8). A field can be absent from the body and still be rendered; it can also be present in
metadata and never reach the page.

| What you are looking for | English | Bengali |
|---|---|---|
| Article body (markdown-ish prose) | `BLOG_BODY` — `src/data/blogContent.ts` | `BENGALI_BLOG_OVERRIDES[slug].content` — `src/data/bengaliContent.ts` |
| Title, summary, category, dates, author, read time | `BLOG_DATA` — `src/constants.ts` | override fields — `src/data/bengaliContent.ts` |
| `references` | `BLOG_DATA[].references` | `BENGALI_BLOG_OVERRIDES[slug].references` (falls back to the EN post) |
| `internalLinks` | `BLOG_DATA[].internalLinks` | `BENGALI_BLOG_OVERRIDES[slug].internalLinks` (**no fallback**) |
| `affiliateCTA` | `BLOG_DATA[].affiliateCTA` | `BENGALI_BLOG_OVERRIDES[slug].affiliateCTA` |
| `inlineFigure`, cover image | `BLOG_DATA[].inlineFigure`, `getBlogCoverImage` in `src/utils/blogCoverImages.ts` | override, shared asset |
| Scheduled drafts | `content/blog/*.md` → `src/data/*.generated.ts` | same file |

Scheduled posts are generated by `npm run generate:scheduled` (`scripts/generate-scheduled-blogs.ts`). **Never
hand-edit a `*.generated.ts` file**; edit the Markdown draft and regenerate.

## 2. Definition of done — six gates

An article is finished only when all six are true, in **both locales**:

1. **Body** — answers the page's one job, with claims backed by dated primary sources (§5, §6).
2. **Sources** — at least three references, primary first, with `name`, `nameBn`, `url` (§5).
3. **Links** — at least four internal links, of which at least two are blog→blog and at least one is a hub or money
   page; no dead, duplicate or self targets (§3).
4. **Commerce** — one relevant `affiliateCTA` (or an explicit decision that there is no relevant partner) (§4).
5. **Locale parity** — the Bengali twin carries the same facts, the same caveats and its own explicit links (§6.4).
6. **Build proof** — `npm run lint`, `npm run build`, `npm run verify:build` exit 0, and the new anchors exist in
   `dist/` for both locales (§8).

A green `verify:build` does **not** satisfy gates 1, 2 or 5. CI cannot read prose.

## 3. Internal linking contract

### 3.1 The map

```
/umrah (pillar)  ──  Umrah specialist guides (Fard Hajj stays separate and linked)
      │                    │
      │                    ├── lateral: 2–5 sibling posts
      │                    ├── up: pillar / category hub
      │                    └── commerce: /flights, /hotels, /visa, /costs, /tools
      └── every child must be reachable from at least two siblings
```

Link **up** to the pillar or hub, **across** to genuine siblings, and **out** to the one money page that completes the
task. Do not link every sibling from every post; that produces a link farm with no hierarchy.

### 3.2 Rules

- **R1 — Minimum.** Every new or upgraded article defines **≥4** `internalLinks`: **≥2** blog→blog, **≥1** hub or
  money page. Target steady state is 3–5 siblings plus 1–2 hubs.
- **R2 — No orphans.** A new article must be added to **at least two existing articles** in the same release wave.
  Publishing a page that only the index links to is not a release.
- **R3 — No dead, duplicate or self targets.** `/blog/<slug>` must exist; a path may appear once; never link the
  article to itself. Use the current canonical route inventory. `/pre-departure` has its own route;
  older instructions treating it as a `/sitemap` alias are historical.
- **R4 — Anchors are descriptive and varied.** Name the target's subject ("Nusuk app and Rawdah permit
  step-by-step"), not "read more", "click here" or "this guide". Vary the wording for the same target across posts.
  A phrase, not a sentence.
- **R5 — Placement matters.** `internalLinks[0]` is injected as a contextual link inside the body after hydration.
  Put the single most task-relevant link first. The remaining links render in the related box.
- **R6 — One locale is not the other.** `getLocalizedBlogs("bn")` assigns `internalLinks: bn.internalLinks` with no
  English fallback. A Bengali override that omits the array ships an article with **zero** editorial links. Write the
  Bengali array explicitly, in canonical English paths (`/blog/...`, `/umrah`); the renderer localizes them to
  `/bn/...`.
- **R7 — Rendered, not declared.** A link that exists in `BLOG_DATA` but not in `dist/` is not a link. Verify with §8.
- **R8 — Relevance over volume.** Link the page a reader needs next, not every page in the cluster. A visa page does
  not need a hotel link unless hotel choice changes the visa decision.
- **R9 — Shared recommendations supplement curated links.** Both locales require the same automatic
  recommendation selection, with localized titles and destinations. Curated links still supply the deliberate
  reader journey. The current helper scores category, title/slug tokens, explicit links and reciprocal links;
  those signals do not establish editorial relevance on their own.

### 3.3 Shared reading components — 5 November 2026

| Locale | Related blog anchors | Hub / money anchors | Extra |
|---|---|---|---|
| Saved HTML, both locales | complete localized curated list + up to three canonical recommendations | curated planning panel and five shared hubs | same header, cover, summary and related cards as React |
| React, both locales | same recommendation selection + curated links | same planning components | first curated link also appears in the body where applicable |

`articleLinkPath` resolves the currency-tool aliases and preserves filters/fragments. The planning component omits
duplicate and self destinations, but authors must still correct such entries in their source arrays. Compare EN/BN
editorial destinations as well as counts; shared rendering does not reconcile different authored link choices.

### 3.4 Worked example — `blog-17`

```
Nusuk app & Rawdah permit        → /blog/nusuk-app-…-rawdah-permit      (sibling, task step)
Hotel zones & Haramain train     → /blog/makkah-madinah-hotel-zones-…  (sibling, logistics)
Umrah with elderly parents       → /blog/umrah-with-elderly-parents-…  (sibling, audience variant)
DIY Umrah portal & calculator    → /umrah                              (up-link, pillar)
```

This illustrates three sibling relationships and a pillar link. Read the current source arrays for the actual
list. Additional English recommendations also need a Bengali counterpart; the earlier allowance for a shorter
Bengali recommendation list is superseded by the owner's 5 November full-parity instruction.

## 4. Affiliate and widget contract

### 4.1 Registry

All partner URLs live in `AFFILIATE_LINKS` (`src/components/AffiliatePartners.tsx`). `affiliateCTA.provider` is a
closed union of those keys. Never hardcode a `.tpo.li` URL in content, a component or a prerender string; resolve
through `resolvePartnerUrl()` or `<PartnerLinkButton />` so paused programmes fall back correctly.

### 4.2 Relevance matrix

| Reader friction | Partner keys | Place it when | Do **not** place it when |
|---|---|---|---|
| Comparing airfare / open-jaw routes | `aviasales`, `kiwi` | the article compares routes, carriers, baggage or fare timing | the article is about a visa rule or a religious procedure |
| Airport arrival and transfer | `kiwitaxi`, `welcomePickups`, `getTransfer` | arrival logistics, family/elderly travellers, late-night landing, luggage | the article is domestic rail/bus, or the reader is already at the hotel |
| Connectivity and app-based permits | `airalo`, `yesim` | Nusuk/Rawdah QR, multi-country trips, family tracking, remote work | the article has no app, QR or connectivity step |
| Attractions, passes and activities | `klook`, `kkday`, `tiqets`, `goCity` | city itineraries, skip-the-line, day trips, experience comparisons | visa, customs, mahram, medical or legal-procedure articles |
| Hotel-stay search | `klook` | the article compares areas, seasons or booking windows | the article is about a permit that hotels cannot influence |
| Car rental and road trips | `qeeq` | self-drive routes, inter-city road legs | the destination is served by rail and the article says so |
| Luggage storage / long layover | `radicalStorage` | layovers, early check-in, last-day storage | the article is about checked-baggage rules |
| Flight disruption / compensation | `airhelp` | delays, cancellations, denied boarding, compensation | routine planning articles with no disruption scenario |
| Creator referral | `TRAVELPAYOUTS_REFERRAL_URL` | only inside the labelled "For Travel Creators" block | anywhere a reader might mistake it for a booking link |

### 4.3 Rules

- **A1 — One primary CTA per article.** A second, unrelated CTA splits intent and reads as a advertorial.
- **A2 — Every article must leave the reader with a next step, and that step is chosen by the reader's stage, not
  by the article's topic.** There are two commercial layers and they are governed differently:
  - **A2.1 — the primary CTA** (`affiliateCTA`): at most one partner, and it must solve the friction *this* page
    creates. If the page is about mahram rules, a family transfer does not solve it; a women's-access question needs
    an answer, not a taxi. If no partner answers the page's own friction, the primary CTA is omitted.
  - **A2.2 — the Journey Help panel** (`journeyHelp`, §4.4): a separate, always-present block that shows the reader
    what their *next* practical problem will be, with 2–3 partner links and a written reason for each.

  The old rule said "ship no CTA and say so". That is withdrawn: **no article ships with no commercial layer at all.**
  What replaces it is stricter, not looser — a partner may only appear in a stage where it genuinely helps (§4.4),
  the panel is capped at three links, each link carries a specific reason, and every link is measured. A reader who
  has just been told how to count seven circuits gets a SIM card and a transfer, never a city attraction pass.
- **A3 — Provider keys only.** `affiliateCTA.provider` must be a key of `AFFILIATE_LINKS`; CI rejects anything else.
- **A4 — Specific copy, not a slogan.** Name the airport, city or route the reader is actually using. "Landing at
  Jeddah Terminal 1 in Ihram?" is specific; "Book your transfer today!" is not.
- **A5 — Disclosure and attributes.** The rendered CTA carries the site disclosure; outbound affiliate anchors use
  `rel="noopener noreferrer sponsored"`. Never add `nofollow` to editorial references.
- **A6 — Promotions expire.** Any coupon, sale or price claim in CTA copy must pass through `isPromoActive()` and
  `sanitizeExpiredPromoText()`. Do not hardcode a promo date into prose.
- **A7 — Article CTAs render in both representations.** Since the 5 November static-CTA repair,
  `renderBlogAffiliateCtaHtml` emits every declared article CTA in saved EN/BN HTML. `BlogPostRouteView` renders
  the interactive equivalent. Both use the partner registry and evergreen disclosure. Verify the actual link and
  localized wording; other contextual placements have their own rendering paths.
- **A8 — No fake relevance.** Never attach a partner to a page whose intent it does not serve merely to raise
  revenue. The owner reviews this as an editorial decision.

### 4.4 The Journey Help panel (`journeyHelp`)

**Why it exists.** The reader of a Hajj or Umrah article is on a journey with a fixed sequence of practical
problems — visa, flight, arrival transfer, connectivity, accommodation, the rites themselves, then customs on the
way home. An article answers one of those and then abandons the reader at the next one. The panel closes that gap:
it shows what the *next* problem is and who can help with it, on the page the reader is already on.

**Why it is not a licence to advertise.** Because the panel is chosen by **stage**, not by article, and a stage only
carries partners that genuinely serve it. A stage with no suitable partner carries no links — the panel still
renders, with internal links and no commercial link.

#### 4.4.1 The four stages

Every Hajj & Umrah article declares one stage (new optional field `journeyStage` on `BlogPost`):

| Stage | Reader is doing | Panel partners, in order | Never |
| --- | --- | --- | --- |
| `prepare` | visa, registration, documents, budget | `airalo` / `yesim` (connectivity for Nusuk and Rawdah QR), `kiwitaxi` / `getTransfer` (arrival), `klook` (hotel search) | attraction passes, `airhelp` |
| `travel` | flights, airport, Ihram, transfer | `aviasales` / `kiwi` (fares), `kiwitaxi` / `welcomePickups` (arrival), `airalo` / `yesim` (SIM), `radicalStorage` (bags) | `qeeq` (no self-drive), `goCity` |
| `perform` | the rites themselves, inside Makkah/Madinah | `airalo` / `yesim` (Nusuk and Rawdah QR, family tracking), `radicalStorage` (bags during rites), `kiwitaxi` (Makkah ⇄ Madinah ⇄ Mina transfer) | **airfare**, **attraction passes**, `airhelp` |
| `return` | departure, customs, Zamzam, delays | `airhelp` (delay, cancellation, baggage), `radicalStorage` (last-day bags), `airalo` / `yesim` (roaming before landing) | `klook`, `goCity` |

The `perform` row is the one that matters most and the one most likely to be argued for. It stays as written:
a pilgrim counting circuits is not shopping for a fare, and putting one there would be the clearest possible
breach of A8.

#### 4.4.2 Panel contract

- **Maximum three commercial links.** More reads as an advertorial block and dilutes the click.
- **Every link carries a written reason** of one line that names the reader's actual next problem. "Get connected
  before your Rawdah slot" passes; "Book now and save" fails A4.
- **The panel is labelled.** It sits under a heading that says what it is (e.g. "Before your next step") and carries
  the site disclosure (A5). It must not look like an editorial recommendation.
- **It is additive to internal links, never a substitute.** An article's internal links still carry the reading job;
  the panel carries the logistics job. A page that has a panel and thin internal links fails G4.
- **It is client-rendered**, so it does not add to the static HTML (A7). If it must be crawlable, that is a code
  change in `scripts/prerender.ts`, not a copy change.
- **It is optional per article**, but its absence must be a decision: the article's queue row records
  `journeyHelp: none — <reason>`, in the same way the old rule required.

#### 4.4.3 Measurement

Every panel link fires `affiliate_partner_click` with `affiliate_placement: "journey_help"`, which the existing
tracker already carries (`src/utils/analytics.ts`). That means the moment GTM forwarding is live, the panel is
measured against the primary CTA on the same page: if `journey_help` out-clicks the primary CTA over 30 days, the
panel should become the primary and `affiliateCTA` should be reconsidered — and if it earns nothing, it comes off.

**A panel nobody clicks is a banner. Delete it rather than insist on it.**

**Status: built 2 November 2026.** `src/utils/journeyHelp.ts` (stage → partners),
`src/components/JourneyHelpPanel.tsx` (render, disclosure, `data-affiliate-placement`),
`journeyStage` on `BlogPost`, rendered in `BlogPostRouteView` directly above the
related-links block. Guarded by `scripts/test-journey-help.ts` (13 checks), which
asserts the stage→partner rules including the one that matters most: `perform`
cannot carry a fare or a compensation link. All 13 Hajj & Umrah posts carry a
stage (7 prepare, 3 travel, 2 perform, 1 return).

## 5. Sources and external links

- **S1 — Three sources minimum** for a new or materially upgraded article. Primary first: ministry, regulator,
  airport, airline, operator, property. A news article or another blog is a lead, not a source.
- **S2 — Shape.** `{ name, nameBn, url }`. Both names are required; the Bengali page renders `nameBn`. No affiliate
  URLs, no URL shorteners, no tracking parameters that expire.
- **S3 — Cite in prose with `[n]`.** Bodies contain markers, not raw URLs. The highest marker must not exceed
  `references.length`.
- **S4 — Date the check.** Set `updatedAt` only when you actually re-checked the claim; the renderer prints
  "References checked: <date>" from it. Do not set a fresh date on unchanged copy.
- **S5 — Attributes.** References render as `target="_blank" rel="noopener noreferrer"`. Affiliate anchors add
  `sponsored`; editorial sources never do.
- **S6 — Cite the operator, not the intermediary.** If a competitor's guide states a fare, cite the airline or
  operator page it used. Do not make a competitor the authority.
- **S7 — Volatile facts.** Put the date basis beside the number ("checked 17 October 2026"), state the condition
  (date, room, occupancy, class), and if the source cannot be re-verified, **delete the claim** rather than soften it
  into vagueness.
- **S8 — External links belong in the sources block.** Inline external links are for the primary document a reader
  must open to complete the task, not for background reading.

## 6. Voice and structure

### 6.1 House voice

Calm, direct, locally informed, candid about uncertainty. Speak to a traveller planning from Bangladesh; BDT first
when a verified price exists; name the passport and departure context. Lead with the reader's friction and answer
the primary question without hype. Never imply URAL booked, tested, interviewed or measured anything unless the
repository contains that evidence. Full contract: [`AI-WRITING-PROMPTS.md`](AI-WRITING-PROMPTS.md) §0.5.

### 6.2 Upgrade pattern — the "conversational" style, defined

The style used in the October 2026 upgrade wave (the Cox's Bazar pillar is the reference article) is not loose
chattiness. It is a fixed five-beat structure:

1. **"Who this guide is for"** — one sentence naming the reader, their origin and their decision. No generic intro.
2. **"Quick Answer"** — the dated, specific answer in the first two sentences, with citation markers.
3. **Question-shaped headings** — "Cox's Bazar Airport Status in 2026: International Flights Still Suspended", not
   "Airport".
4. **The practical detail** — cost, condition, document, step, with the date basis beside it.
5. **The caveat beside the claim** and the next action, linked (§3).

Write to one traveller, in the second person, in short factual sentences. Conversational means *direct*, not casual:
no filler ("In today's world…"), no jokes in a religious or legal section, no "we" unless the repository contains the
evidence for it.

```text
YES  Who this guide is for: families leaving Dhaka who need a plan they can verify today.
YES  Quick Answer — As of 16 October 2026, three routes operate: … [5]. International flights are not operating: … [2].
NO   Planning a trip to Cox's Bazar? Read on to discover everything you need to know!
```

### 6.3 Factual vs practical sections

Factual sections (rules, fees, eligibility) run definition → rule → attribute → source. Practical sections
(choices, trade-offs, planning) may use first/second person and editorial judgement, but may not invent experience,
reviews or community answers. Component and visual rules: [`CONTENT-SYSTEM-V2.md`](../02-content/CONTENT-SYSTEM-V2.md).

### 6.4 Bengali parity

The Bengali article must answer the same questions with the same eligibility, prices, date basis, exclusions,
warnings, route steps and source links. It must carry the same section hierarchy, features, components, SEO/AEO
coverage, editorial destinations, related recommendations and commercial actions as English, in both saved HTML
and the running browser. It also needs its own explicit `internalLinks` with Bengali anchors (R6).

Write native, correct Bengali with its own sentence rhythm. Preserve technical, industry and aviation terms in
English when that is the accurate wording, including PNR, open-jaw, eSIM and IATA codes. Ordinary prose should read
naturally in Bengali. Equal word or heading counts cannot certify equal coverage or writing quality.

### 6.5 Banned phrases

"hidden gem", "insider secret", "you won't believe", "guaranteed approval", "100% free" without a source,
"best" without stated criteria, invented "we tested / we stayed / our team visited", and urgency that the calendar
does not support.

## 7. Procedure

1. **Read the current authorized task and baseline.** Confirm the URL, the action (new / update in place) and the page's one job. Old queue rows and cluster plans supply history, not authorization.
2. **Inspect the live representation.** Open the rendered EN and BN pages and the three source locations in §0.
   Record the current link count, CTA provider and reference count.
3. **Build the claims ledger** ([`CONTENT-OS.md`](CONTENT-OS.md) §3, prompt in `AI-WRITING-PROMPTS.md` Stage 2).
4. **Rewrite the body** with `[n]` markers and the §6 pattern.
5. **Wire the metadata:** `internalLinks` (≥4, ≥2 blog), `affiliateCTA` (or a recorded decision to omit),
   `references` (≥3), `updatedAt`.
6. **Write the Bengali twin:** body, summaries, references with `nameBn`, and its own `internalLinks`.
7. **Update the dates truthfully:** per-post `updatedAt` for the article; `CONTENT_UPDATED` in
   `src/data/contentMeta.ts` only when non-blog, data-driven content changed under its documented date contract.
8. **Build and verify:** `npm run lint && npm run build && npm run verify:build`.
9. **Prove it in `dist/`** (§8), then update the queue row and the claims ledger.

## 8. Verification

```bash
npm run lint
npm run build
npm run verify:build
```

Then inspect the built pages — not the browser, not the source:

```bash
# every curated blog link is a real anchor (EN)
grep -o 'href="/blog/[^"]*"' dist/blog/<slug>.html | sort -u

# the Bengali twin has its own anchors (BN)
grep -o 'href="/bn/blog/[^"]*"' dist/bn/blog/<slug>.html | sort -u

# the sources block rendered
grep -o 'Sources for this guide' dist/blog/<slug>.html

# expected: the declared partner URL is present when this article uses Kiwitaxi
grep -c 'kiwitaxi.tpo.li' dist/blog/<slug>.html
```

If a count is lower than the metadata says, the link did not ship. Fix the renderer or the metadata; do not report
the metadata as proof.

## 9. What CI enforces

`npm run verify:build` now includes a **content contract** block:

| Check | Scope | Fails when |
|---|---|---|
| Link integrity | English declared arrays | an empty link list, a non-absolute path, a self-link, a duplicate path, or a `/blog/` target that does not exist |
| Provider integrity | all posts | `affiliateCTA.provider` is not a key of `AFFILIATE_LINKS` |
| Flagship minimums | Hajj & Umrah | fewer than two blog→blog links, or no affiliate CTA |
| Rendered anchors | Hajj & Umrah | a curated `/blog/` link is absent from the EN page, or the BN page has fewer than two `/bn/blog/` anchors |
| Bengali next reading link | every Bengali static article | no in-locale article anchor is rendered; this minimum is not a full parity comparison |
| Declared affiliate next step | static EN/BN articles | the declared partner's sponsored link is absent |
| Schema URL localization | client-used URL helper | a schema type, date, language code or prose is converted into a site URL, or a genuine page URL is localized incorrectly |
| Shared article presentation | saved HTML and React, every EN/BN pair | a full summary, byline field, canonical date, responsive cover, planning link/label, related card or unique section ID is lost |
| Automatic recommendations | every published article | translated titles, categories or link arrays change the canonical recommendation selection |
| Negative control | fixtures | the validator stops catching a deliberately broken fixture |

The validator is tested against broken fixtures on every run, so a refactor cannot silently neuter it.

**Not enforceable by CI:** whether a link is the *right* next step, whether the CTA answers the page's friction,
whether a source is primary, whether the Bengali text is a real localization, or whether a claim is true. Those
remain human gates.

The build also prints a non-blocking **`[content-debt]`** report: posts with no blog link, no CTA, no references, and
posts with no editorial inbound link. Green CI is not a pass on those items; it is a record of them.

## 12. Owner authoring rules — 12 November 2026 (normative)

These four rules came from the owner while reviewing the first UK pillar article. They apply to
every article written or localised from this date, and they are checks, not preferences.

### 12.1 One market per article — no cross-market filler

An article written for one market's audience must not carry the other market's material. **A UK
article never mentions Bangladesh, Dhaka, BDT or the Bangladesh-side flow** — not in the summary,
not in a bullet, not as a "what changes if you hold X passport" section, not as an internal link
to a Bangladesh-only guide.

Where a passport question genuinely arises, write it market-neutrally: *"the table is the British
citizen passport track; the official eVisa portal publishes the eligible countries, and for any
passport not on that list the instruction is to contact the nearest Saudi Arabia Embassy."*

Inbound links into the article may come from other markets (that is how G4 is satisfied); the
article's own body and metadata stay in one market.

### 12.2 The Quick Answer block is an AEO asset

The frontmatter `summary` renders in the **Quick Answer & Key Takeaway** block above the fold, and
also feeds the meta description and RSS, so it is the passage an AI answer engine is most likely to
extract. Write it as one:

- **Answer first, in the first sentence.** No throat-clearing, no "this guide will explore".
- **Every claim dated** — "checked 12 November 2026" — and only facts that are green in the article.
- **Dense with extractable specifics:** numbers, route names, airports, deadlines, prices with
  their source. A model should be able to quote a sentence and be right.
- **No markdown.** This block renders as plain text (`QuickAnswer`), so `**bold**`, lists, tables and
  links are not supported there — they will appear as literal characters. Links belong in the body.

### 12.3 Tabular data is a table, never a paragraph

If the content compares two or more things across two or more attributes, it is a table:

| Do | Do not |
| --- | --- |
| A real pipe table (`\| Item \| Source \| Status \|`) | The same rows written as sentences |
| One row per item, one column per attribute | "For the ETA it's A, for the e-visa it's B…" |
| A header row, so a crawler reads column names | Bullet lists standing in for columns |

Both renderers now emit real `<table>`/`<thead>`/`<th scope>` markup
(`scripts/prerender.ts` → `renderMarkdownTableHtml`, `src/routes/BlogPostRouteView.tsx` →
`parseMarkdownTableBlock`). This replaced the earlier observation that Bengali posts carried no
tables — that was inherited habit, not a technical limit. **Bengali articles use the same tables as
English, with translated headers and cells.**

### 12.4 Every reference is a clickable anchor

- Internal and external links are authored as `[descriptive anchor text](url)`. Bare URLs, "click
  here", and "see the link below" are defects.
- The anchor describes the destination ("the Nusuk BRN and Rawdah permit chain"), never "read more".
- Source URLs belong in frontmatter `references` (rendered as a linked sources list); prose links
  point at pages a reader would actually open.
- After any build, grep the rendered HTML for `](` — a match means a markdown link failed to become
  an anchor.

**Verification for 12.1–12.4:** `npm run build`, then check the locale's `dist/…html` — real
`<table>` count, zero `<p>|`, zero `](` left as text, and zero off-market terms inside `<article>`.

### 12.5 Every flight link goes to the white label — no exceptions in content

A flight next step must resolve through `resolveBookingCtaUrl(provider, { slug, locale })`
(`src/utils/bookingCta.ts`), which returns `https://flights.uraltravel.co.uk/?currency=…&locale=…&sub_id=post_<slug>`.
The `sub_id` is what makes a click attributable to the article that earned it; without it every
article CTA is one indistinguishable row in the Travelpayouts report.

Rules:

- Never paste `aviasales.tpo.li/…` or `aviasales.com/search/…` into article copy, an `affiliateCTA`,
  a `MULTI_PARTNER_BLOG_PLACEMENTS` block or a FAQ answer. The branded site keeps the money but loses
  the brand and the per-placement attribution.
- Widgets keep their inline search (they already build the white-label URL) and the article CTA is the
  fallback for readers who never hydrate.
- `npm run verify:build` scans every `dist/blog/**/*.html` and fails if either Aviasales host appears,
  and re-checks that each declared `affiliateCTA` renders with its expected white-label href.
- Partner logo tiles are the one deliberate exception: a logo advertises the partner, so it links to
  the partner's tracked short link.

**Verification:** `npm run build && npm run verify:build` — the check reads
"no blog page links to the Aviasales-branded site".
