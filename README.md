# URAL Travel Intelligence

Travel planning for Bangladeshi travellers and anyone flying out of Dhaka: flight
and hotel comparisons, visa and e-Visa routes, DIY Umrah and Hajj guides, and BDT
trip budgets. Every published money figure carries a date and a source, or it does
not render — see [PRODUCT.md](PRODUCT.md).

**Live site:** <https://uraltravel.co.uk> · **Languages:** English (`/`) and Bengali (`/bn/…`)

---

## Quick start

```bash
nvm use          # Node 22 (see .nvmrc)
npm ci           # npm only — the repo has no bun lockfile, by design
npm run dev      # http://localhost:3000
```

`npm run dev` regenerates the scheduled-post modules and the site-search index
before starting Vite, so a clean checkout behaves like an existing worktree.

> **There is no `.env` file.** The site is a static build plus a handful of
> Cloudflare Pages Functions. Secrets are read at *request* time from the Pages
> runtime, so they live in the Cloudflare dashboard — [`.env.example`](.env.example)
> is a checklist of what to set there, not something Vite loads.

## What this project is

| Piece | What it does |
| --- | --- |
| `src/App.tsx` | Client router, layout and page composition (no react-router — paths are parsed from `window.location`) |
| `src/components/`, `src/routes/` | Pages, lazily imported so the homepage does not ship the whole corpus |
| `src/data/`, `src/constants.ts` | Content records: flights, hotels, visas, destinations, costs, blogs |
| `content/blog/*.md` | Blog source. Build scripts generate `src/data/scheduledBlog*.generated.ts` (gitignored) |
| `scripts/prerender.ts` | Emits one real HTML file per canonical route (152 EN + 152 BN), plus sitemap, RSS, og-image and blog JPEGs |
| `scripts/verify-build.ts` | ~600 assertions over the built output. This is the safety net; treat a failure as a real bug, not noise |
| `functions/` | Cloudflare Pages Functions: `/api/contact`, `/api/subscribe`, `/api/confirm`, `/api/rates`, plus routing middleware |

## Everyday commands

| Command | Use |
| --- | --- |
| `npm run dev` | Dev server on port 3000 |
| `npm run dev:drafts` | Same, but includes unpublished/future posts |
| `npm run build` | Production build: generate → Vite → prerender. **Run this before `verify:build`** |
| `npm run verify:build` | Asserts the built HTML, sitemap, RSS and asset rules. Needs `dist/` |
| `npm run lint` | `tsc --noEmit` (the only static check — there is no ESLint yet) |
| `npm run test:<name>` | One focused suite; see the list in `package.json` |

There is no `npm test` aggregator: the suites are 38 individual `test:*` scripts.
CI runs every one of them, plus `lint`, `build` and `verify:build`, and
`verify-build.ts` fails if a suite exists in `package.json` but is missing from the
workflow. Suites that read `dist/` must be listed *after* the build step.

## Deploying

Cloudflare Pages builds and deploys from `main` through its own GitHub integration —
**CI does not deploy**, on purpose, so there is only one source of truth.
`npm run build` produces `dist/`, which is what Pages serves.

| Concern | Where it is handled |
| --- | --- |
| Sitemap / RSS freshness | Committed to `public/`, regenerated by the build, and CI fails if a build rewrites them (they must be reproducible) |
| Scheduled blog posts | `.github/workflows/scheduled-publish.yml` checks Dhaka publish dates and POSTs a Cloudflare deploy hook |
| Caching and security headers | `public/_headers` (read the comments before editing — paths merge, they do not override) |
| Redirects | `public/_redirects` (static aliases) and `functions/_middleware.js` (legacy query-string URLs) |
| Search-engine notifications | `INDEXNOW_SUBMIT=1` on the production build only; off by default so PR builds never announce URLs |

## Conventions worth knowing

- **Generated files are never committed.** `src/data/scheduledBlog*.generated.ts`,
  `public/site-search-index.json`, `public/og-image.jpg` and `public/img/blog/` are
  build output.
- **Bengali is a first-class surface,** not a translation layer: `/bn/…` is
  prerendered, self-canonical and independently indexable. Route groups without a
  Bengali counterpart are listed in `src/utils/localeRoutes.ts` and resolve to the
  English page rather than a broken `/bn/` path.
- **Every route renders from real HTML at first paint.** If you add a route, add it
  to the prerender list and to the sitemap tests, or it will only exist after
  hydration.
- **A `.claude/` directory and several strategy documents exist at the root.** They
  are working material for how this repository is maintained, not part of the
  application.

## Roadmap notes

Two known gaps, recorded here so they are not mistaken for finished work:

- **The newsletter list needs three secrets to exist.** Since 17 November 2026 a
  signup is a real double opt-in: the address lands in a Resend segment marked
  unsubscribed, a signed confirmation email flips it, and broadcasts carry Resend's
  own unsubscribe. It only works when `RESEND_LIST_API_KEY`, `RESEND_SEGMENT_ID`
  and a sending key are all set — see [.env.example](.env.example). Without them the
  endpoint falls back to notifying the desk and answers `pending: false`, so the
  page never claims a confirmation that did not happen. See §6 of
  `docs/growth/20-FORM-AND-MAIL-HARDENING-2026-10-25.md`.
- **Both mail endpoints are hardened but per-isolate.** The rate limiter is
  best-effort; the real control is a Cloudflare WAF rate-limiting rule on `/api/*`.
