# URAL — Master Content Optimization Guide

**Lifecycle: CURRENT WORKING STANDARD · Established 26 October 2026**\
**Purpose:** make an existing page more useful, accurate and connected; create a new page only for a genuinely unserved reader task.

This is the authoritative synthesis of URAL's existing content methodology. It governs **how** authorized content work is researched, briefed, written, localized, connected and checked. The current owner request determines **which** work proceeds. The [social content ecosystem](URAL-SOCIAL-CONTENT-ECOSYSTEM.md) applies this standard to existing-content repurposing.

Read alongside [AGENTS.md](AGENTS.md) for repository rules and the [article acceptance contract](docs/growth/10-CONTENT-UPGRADE-STANDARD.md) for field-level implementation and verification. Original research and dated source records remain supporting evidence. The [current audit](00-URAL-CURRENT-AUDIT.md) is a dated diagnostic baseline, not a certification of every live claim.

## Quick start

For one authorized asset:

1. Identify its existing URL, audience, language, **one reader decision** and next useful action.
2. Inspect the complete page: body, metadata, summaries, references, editorial links, CTA, Bengali twin, saved HTML and interactive rendering.
3. Map relevant questions to **this page, a heading, a short answer, an existing link, or defer**.
4. Verify material claims with the responsible sources; record applicability and dates.
5. Write a short brief with the answer, section formats, evidence, differentiation and link plan.
6. Improve the approved asset; preserve its URL and useful material. Localize at decision-level parity.
7. Check every representation and the actual next-action destination.
8. Pass editorial and build gates; report the exact result. Publication follows the owner's authorized release scope.
9. Measure useful outcomes and record what the evidence justifies doing next.

**Success:** a traveller can make a better decision before spending money. Word count, keyword repetition, schema presence and a green build cannot establish that on their own.

## 3. Reconciliation decisions

| Older instruction / apparent conflict | Working resolution |
|---|---|
| Cover the entire query network; publish densely | Cover the verified questions needed for the selected task. Map adjacent jobs; do not create pages to satisfy a completeness percentage |
| Add 20–30% more than competitors / inspect up to eight sites | Identify the smallest evidence-backed improvement that completes the task. A focused page comparison is enough unless a specific question remains unresolved |
| Repeat source-context attributes in almost every article | Use passport, departure, currency and family constraints only where they change the answer |
| Tool-first for functional intent | Use a working, accurately described existing tool when it helps. A misleading handoff fails usefulness; a new tool needs its own task |
| Every section must use a named component | Specify a supported **format** and prove the output. Plain prose is valid. A brief cannot invent renderer functionality |
| Factual definition → rule → attribute opening | Use when it clarifies. Lead with the important condition when the source or reader's question requires it |
| No repeated information between table and prose | Avoid duplicated explanations; a concise accessible summary of a table is useful when it adds interpretation |
| One cost table versus multiple comparison options | One consistent model/basis; multiple options may be columns in it. No contradictory independent totals |
| “Always” attach a relevant affiliate CTA | The contract allows a documented omission when none genuinely fits. Current Hajj & Umrah verification expects a CTA: resolve an intended exception explicitly, never add an irrelevant offer just to pass |
| Three references versus quality over quantity | Retain the ≥3 primary-reference acceptance floor. Choose sources that support actual claims; if the job cannot justify that, resolve scope/contract applicability rather than padding a list |
| Upgrade article only versus two incoming links for a new article | A new article's authorized release includes the small relevant inbound-link changes. That is not permission to rewrite neighbouring articles |
| “Check only dist” versus client-only CTA | Inspect both. Static content is crawlable evidence; the hydrated CTA, widgets and handoffs require a browser/behavior check |
| Bengali must render identically | Same decisions, facts and functioning formats; natural language can differ in length and phrasing |
| Wait ~90 days / fixed 30-day or 21-day campaign | Use the selected task's cadence and sufficient comparable evidence. The new social programme derives its length from assets and workload |
| “No GSC data” in earlier documents | The owner supplied corrected historical pages.dev data and very early .co.uk signals on 26 October. Keep properties separate; date ranges/filters remain missing. See [search evidence](docs/03-social/SEARCH-EVIDENCE.md) |
| Old pruning/redirect suggestions | Preserve existing URLs and value; low or unknown traffic alone justifies neither deletion nor redirection |
| Existing source copy is automatically safe social copy | Reassess the actual claim, locale and landing-page promise. Unsupported source claims become NEEDS-UPDATE, not shorter overclaims |

Rejected practices remain rejected: invented experience/reviews/community answers; keyword stuffing; mass duplicate pages; fake urgency or savings; AI-detection evasion; proxy/account-warming rituals; randomized posting to evade filters; link schemes and spam syndication. This is an editorial quality standard, not an algorithm-manipulation recipe.

## 4. Intent and query mapping

### Start with the traveller's job

Complete this sentence:

> For **[reader, passport/residence and origin where relevant]**, this page helps decide **[one decision]** at **[planning stage]**, using **[evidence]**, then leads to **[useful next action]**.

“Umrah” is a topic. “Compare three flight-route shapes on the same passenger and cost basis” is a page job. “Buy a live airline ticket” is a different job; an editorial guide should help the reader reach a service that actually performs it.

### Query roles

| Role | Meaning | Use |
|---|---|---|
| Primary query / family | Best shorthand for the page's main decision | Title/H1 and early answer, naturally worded |
| Secondary queries | Sub-questions needed to finish that same decision | H2/H3 sections, comparison criteria or procedural steps |
| Supporting queries | Definitions, qualifiers and exceptions | Short explanations close to the claim |
| Adjacent intent | A different decision already owned elsewhere | Brief bridge and descriptive link |

Use GSC first for observed visibility, existing keyword research for candidate language, then the inventory/audit and bounded SERP checks. Record property, period, country/language, device/search type and exact source when available. GSC impressions show that a property appeared, not total market volume. A keyword workbook's label is a hypothesis. Social comments reveal questions, not national search demand.

Keep historical pages.dev results separate from .co.uk results. Page totals cannot be joined to query rows without a query-by-page export. Do not assign the endorsement page's five historical clicks to any particular query when the supplied query table reports zero clicks.

### Compact query map

| Query / natural question | Evidence and date | Reader intent | Entity + relation | Answer format | Owning URL | Verdict |
|---|---|---|---|---|---|---|
| “umrah cost from bangladesh” | Owner's historical query row: 1 impression, 0 clicks; period unspecified | Build a budget | Trip → component costs → whole-party total | One scoped model / worksheet | `/umrah` | Update existing owner when authorized |
| “Which visa route fits my documents?” | Existing process guide + official source record; demand not measured for this exact wording | Establish eligibility/process | Passport/residence → visa category | Conditional sequence | Existing DIY article | Heading / section |
| “Which hotel entrance works for my parent?” | Existing elderly/hotel guides; editorial question | Assess access | Traveller mobility → property entrance → intended gate | Property-question checklist | Elderly or hotel guide, according to task | Link to specialist owner |

These are planning examples, not fresh travel-rule assertions.

### Update-versus-new decision

1. Existing URL owns the job → **UPDATE IN PLACE** or **KEEP**.
2. Same job but missing a substantial sub-answer → **QD-HEADING**.
3. A qualification or short answer → **QD-SECTION**.
4. Another live URL owns it → **QD-LINK**.
5. Distinct job, adequate evidence, useful format, maintainable scope and no existing owner → **QD-PAGE**, proposed for the owner's selected scope.
6. No useful evidence, weak fit or insufficient need → **DEFER / DROP IDEA**. Dropping an idea does not delete an existing URL.

Similar terms on two pages do not by themselves prove cannibalization. Compare their jobs and, when available, their query-by-page evidence. Resolve repeated answers and titles before proposing a redirect.

## 6. Evidence and source requirements

### Use two separate classifications

**What kind of statement is it?**

- **FACT:** directly supported observation or applicable source wording.
- **INFERENCE:** interpretation beyond direct observation; show the reasoning and limits.
- **RECOMMENDATION:** proposed action based on facts and constraints.

**Can the particular claim be published?**

- `VERIFIED`: source supports the exact claim and scope.
- `QUALIFIED`: only the bounded wording is supported; publish the qualification with it.
- `CONFLICT`: sources or required copy disagree; resolve or describe the conflict accurately.
- `UNVERIFIED`: evidence is unavailable or inadequate; omit the assertion and, where useful, give the checking route.
- `DROP`: unnecessary or unsupported claim removed from the proposed copy.

An official source can support one clause without supporting the whole sentence. A portal homepage is not evidence of an unpublished fee. A failed retrieval is not proof that a rule, route, fare or source does not exist.

### Claim-specific source owners

| Claim | First source to consult | Required scope |
|---|---|---|
| Visa/entry/Umrah season | Responsible ministry, embassy or official visa service | Passport, residence, visa category, travel period; distinguish application, visa, admission and permit |
| Bangladesh Hajj process | MoRA / official Hajj portal and dated circular | Hajj year, registration stage, applicant type; distinguish old packages from current offers |
| Health or medication requirements | Current responsible health authority; treating clinician for personal advice | Season, origin, age/condition and document revision; no personal clearance from a blog |
| Religious practice | Attributed recognized religious source/scholar appropriate to the question | Distinguish a published ruling from personal advice and administrative permission |
| Quota, endorsement and banking | Bangladesh Bank instrument + issuing bank's current implementation/terms | Effective date, resident category, account/card type, transaction purpose |
| Flight or baggage | Operating airline's ticket, dated checkout and terms | Every segment, direction, fare family, pieces/weight and connection arrangement |
| Rail/transfer | Operator terms and dated booking/quote | Stations, dates, baggage, transfer legs and inclusions |
| Hotel/access | Property response/booking terms plus defensible route evidence | Exact room, occupancy, entrance, intended destination, dates; area names prove no accessibility |
| eSIM / SMS | Exact operator plan and support documentation | Data versus SMS/voice, device, network, activation and bank OTP delivery route |
| Comparison / saving | Matched dated baskets and transparent arithmetic | Same dates, party, services, taxes, change terms and quote currency |
| URAL's experience/results | Retained first-party records, owner-confirmed service scope or analytics | What was actually tested, delivered, received or paid; no invented testimony |

Use news, competitors, vendor case studies and search snippets to discover questions and primary sources. Where a report itself is the evidence, attribute it as a report rather than turning it into a universal rule. Record source ownership; a network report about selected successful partners is not a representative forecast for a new publisher.

Use ISO dates in the ledger. A website's moving masthead date is not an article's publication date. Keep a source's publication date, your access date, the rule's effective period and a quote's travel dates distinct.

### Reference-list rules

- Retain the acceptance floor: **≥3 useful primary references** for a new/materially upgraded article, with `{ name, nameBn, url }`.
- Cite the actual provision, operator page or document supporting the claim; preserve qualifications beside the answer.
- Established bodies use supported `[n]` citation markers and matching ordered references. Markdown publishing sources follow their actual parser contract; do not blindly convert all sources to one format.
- No fabricated references, unused decorative citations, affiliate short links or expiring tracking parameters in the evidence list.
- Use direct official links for actions a reader must perform. Descriptive source labels identify what the link proves.
- A missing article-specific metadata array is different from no mention of sources; inspect the rendered page before reporting either.

### Prices, totals and dates

Define **dates + party size + room sharing + duration + inclusions/exclusions + currency + quote timestamp** before writing a total. Distinguish official fee, supplier quote, historical estimate, user input and FX conversion. Fixed widget exchange rates are not live rates.

The retained BDT 116,000–132,000 Umrah reference has a 14 October 2026 basis. It is not today's offer. The worksheet adds whole-party inputs; it neither fetches current prices nor proves a saving, and the inspected version does not save or submit the budget.

For a comparison, check sums and identical scope. State what is unknown. Do not turn a lower starting fare into a cheaper complete trip. Six bookings × $200 × 6% is **$72**, before any eligibility/cancellation/payout adjustments, not $720.

## 8. Writing and section architecture

### First useful screen

State the task in the H1; answer it early; make material conditions and evidence dates visible where relevant. Then give the next useful action. Keep the existing URAL brand and components. A short screen cannot hold an entire regulatory decision tree: lead with the deciding condition and route to the detail.

| Intent | Best opening treatment |
|---|---|
| Rule / eligibility | Direct conditional answer and who it applies to |
| Procedure | Outcome + prerequisites, followed by ordered steps |
| Comparison | Criteria-based verdict and one comparable table |
| Budget | Basis and exclusions before any total |
| Functional lookup | Existing working tool with an accurate description |
| Troubleshooting | Symptom, first check and responsible support route |

### Headings and prose

- One descriptive page H1; H2s are meaningful questions/decisions; H3s belong under their parent.
- Under a question heading, answer before background. Name the subject so the passage makes sense on its own.
- Attach the unit, date, route and exception to the claim. Do not leave a decisive qualification in a distant FAQ.
- Use lists for steps, tables for comparable values, prose for nuance and a figure only when it explains something.
- Preserve a short interpretation beside complex tables; remove paragraphs that merely repeat every cell.
- Explain who does what, where, and what confirmation is needed. “Check everything” is not an actionable procedure.
- No target word count, entity quota, keyword density or competitor-length multiplier. Each paragraph earns its place through a fact, step, decision or necessary qualification.

### Voice

Calm, direct and useful. Write to a traveller rather than to a search engine. Natural second person is appropriate; first-person experience requires actual evidence. Explain costs and trade-offs without agency-bashing. Avoid “ultimate,” “secret,” guaranteed approval, fixed unsourced savings and artificial urgency.

Factual sections need precise definitions and conditions. Practical sections can recommend a choice, but must explain the criteria and introduce no unverified facts. Religious, medical and legal decisions retain their proper distinctions and respectful language.

### Metadata and answer extraction

Align title, H1, summary, search description, AEO answer, body, FAQ, social hook and CTA. A concise answer of roughly 40–60 English words can be a useful drafting guide; it is not a ranking formula or a required Bengali word count. Never remove a material condition to fit it.

FAQs answer real remaining questions specific to the page. There is no automatic eight-question quota. Structured data must match visible content. URAL's referral pages must not describe partner products as URAL `Product`/`Offer` listings. Good answer structure does not promise FAQ rich results, featured snippets or AI citations.

## 9. Internal linking and anchor text

Links are a decision pathway: **prerequisite → current task → next task**.

- Every new/materially upgraded article carries **≥4 curated internal links**, including **≥2 blog-to-blog** and **≥1 relevant hub/money page**.
- A new article needs relevant incoming links from **at least two existing articles** in the authorized release, plus appropriate hub access. Do not link to an unpublished planned route.
- Link up, laterally and toward a useful action; do not link every page to every sibling.
- Use anchors that explain the destination: “compare Jeddah and Madinah flight quotes” is useful; “click here” is not. Vary wording naturally without manufacturing exact-match ratios.
- Place the first curated link at the most useful next decision; the client renderer gives `internalLinks[0]` special contextual placement.
- No duplicate/self/dead targets in curated arrays. Preserve a meaningful existing link rather than replacing it only to vary wording.
- Automatic related posts and global navigation are not substitutes for editorial links.
- Bengali needs its **own explicit array**. Store canonical English paths in the array; the renderer supplies `/bn/` where a twin exists. Verify the exact rendered target, including tool path/fragment behavior.

| From | Anchor reason | Existing destination |
|---|---|---|
| DIY process, before payment | Prepare the card and ask the bank the right questions | Endorsement article |
| Saudi-flight comparison | Carry the same bags on the surface journey | Hotel/Haramain article |
| Hotel access | Plan assistance across the whole journey | Elderly-parent article |
| Umrah eligibility boundary | Follow the separate seasonal process | Hajj registration article |

These describe relationships, not instructions to edit all four pages now.

## 10. Language and localization

**Bangladesh consumer social:** natural Bengali, with familiar terms such as Visa, Passport, Flight, Booking, Nusuk, eSIM and WhatsApp when they make the sentence easier. **International/professional content:** English appropriate to its actual audience. Keep Bangladesh-specific qualifications when the underlying advice depends on them.

Website EN/BN twins retain the same decision, facts, figures, dates, limitations, reference destinations, CTA meaning and useful editorial links. Localize phrasing rather than translating each English sentence mechanically. A shorter Bengali sentence is fine; a missing condition is not.

Check the title, summary, answer, each section, tables/labels, FAQs, sources, link labels, CTA and image alternatives. Keep official portal/product names recognizable. Avoid inventing a separate Banglish URL for a spelling variant of the same intent.

## 11. Commercial actions and social reuse

Answer before asking the reader to act. One primary relevant action is generally enough; an informational or trust asset can end without a sales CTA.

Use the actual affiliate registry and lifecycle functions. Website affiliate anchors require `target="_blank" rel="noopener noreferrer sponsored"`. Editorial references are not affiliate links. Promotional copy must respect expiry in both client and prerendered output.

Verify the promise-to-destination chain:

**Hook → landing-page answer → useful next step → actual handoff → honest completion message.**

Known examples requiring care:

- Hotel selection currently reaches a generic partner page; do not promise preserved city/date/guest selections.
- An eSIM data package does not establish bank SMS/OTP access.
- A contact/alert success message does not establish delivered enquiry, enrollment or ongoing fare monitoring.
- A lookup or quote form does not establish ticket issuance or a service the owner has not confirmed.
- A flight fare label is not a verified current schedule; baggage/Zamzam terms belong to the actual ticket/carrier.

For social, extract **one** supported decision, mistake, comparison or checklist. Give standalone value, then optionally link to the exact useful page. A new format is not a new article. Assign `PROMOTE NOW`, `PROMOTE AFTER UPDATE`, `REPURPOSE SELECTIVELY`, `HOLD` or `FUTURE OPPORTUNITY` at source level; assign production status separately. See the [social ecosystem](URAL-SOCIAL-CONTENT-ECOSYSTEM.md) for the calendar and copy.

### Acceptance checklist

```text
[ ] Authorized asset, URL verdict, one job and scope recorded
[ ] Complete source/client/static inspection; useful content preserved
[ ] Relevant query map and page-boundary decisions
[ ] Claims ledger; no unsupported high-impact assertion
[ ] Body, ≥3 primary references and correct citation mapping
[ ] ≥4 curated links, ≥2 blog links, ≥1 hub/money link, explicit BN links
[ ] Incoming-link plan satisfied for a new page
[ ] Relevant CTA / documented omission, genuine handoff and truthful completion copy
[ ] Full EN/BN decision parity; title, answer, FAQ, schema and CTA agree
[ ] Existing renderer supports the promised formats
[ ] lint, build and verify:build pass; exact outputs inspected
[ ] Publication status and measurement limitations stated accurately
```

Retain the review rubric: **intent/coverage; factual integrity; usability/actionability; locale/trust/release**, each 0–4. Require **≥13/16, no zero and no hard fail**, supported by specific evidence rather than a self-congratulatory score. Wrong eligibility, invented money/experience, contradictory totals, broken critical citations, locale/canonical mismatch or a promised component/action that fails are hard failures.

For website implementation run, in order:

```bash
npm run lint
npm run build
npm run verify:build
```

Inspect the target EN/BN saved HTML and interactive pages. Check references, curated anchors, metadata, dates, FAQs, table/step rendering and the actual CTA. For Markdown FAQs, respect the parser's heading/question-answer pairing; stray paragraphs can break schema despite visible text. Run relevant existing checks when that publishing path changes.

The verifier checks structure, selected claim regressions and rendering; it cannot certify all facts, source quality, translations or business fulfillment. Read its non-blocking content-debt output without turning that whole list into an unauthorized rewrite task. Report repository verification, deployment and indexing as separate states.

## 13. Measurement and maintenance

Measure **attention → useful visit → planning action → received enquiry / genuine partner handoff → confirmed downstream outcome**. Define each metric and its denominator before comparing formats.

- Keep organic-search data separate by domain and period; retain missing fields as missing.
- Use tagged social landing links. Incoming UTM/SubID parameters do not automatically propagate into affiliate links.
- Separate article navigation, affiliate exit, WhatsApp share, contact attempt and received enquiry.
- Separate creator referrals from traveller bookings; pending bookings, approved commission and paid-out revenue are different states.
- Record the actual content change, release date, audience and comparable observation window. Seasonality, indexing and low counts limit conclusions.
- Review high-volatility claims before a scheduled post/release and when an authoritative change is discovered. Do not manufacture freshness by changing dates alone.
- Improve a weak answer or handoff before raising publishing volume. Extend an undersized experiment rather than declaring a niche unsuccessful.

Use dated task/release records for outcomes. Keep this guide as the method, the social register as the production ledger, source reviews as evidence, and archived plans as history. Update authority notes when scope changes so future contributors do not inherit contradictory instructions.
